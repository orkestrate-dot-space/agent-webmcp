# agent-webmcp v1 — locked spec

Locked 2026-11-08. Status: foundation built (polyfill + CLI skeleton, gate
green, uncommitted). This spec absorbs the detailed engineering draft with
corrections from live verification (marked **[LIVE]**).

## 1. Thesis & hard boundaries

Browser drivers give an agent a browser. agent-webmcp turns the websites
inside that browser into a searchable, callable toolkit.

Gaps it closes: pre-navigation blindness (no index of capabilities),
unflagged-browser drop-off (`modelContext` undefined → native tools
discarded), missing capabilities on un-WebMCP'd sites.

Hard rules:

- NO browser ownership: no Chromium/Playwright/Puppeteer, no CDP, no tabs,
  no `open/close/click/snapshot/invoke` verbs.
- NO global/provider abstraction: every tool belongs to a concrete domain,
  `source` is `"native"` or `"custom"`. Per-site, period.
- NO silent telemetry: injected scripts never phone home; nothing uploads
  without an explicit command.
- NO custom registry server: static Git-synced `registry/` + local disk.

## 3. Data model

```typescript
interface ToolEntry {
  name: string; source: "native" | "custom"; description: string;
  inputSchema: { type: "object"; required?: string[]; properties: Record<string, unknown> };
  annotations?: { readOnlyHint?: boolean; consequentialHint?: boolean; untrustedContentHint?: boolean };
}
interface DomainEntry {
  domain: string; entryUrl: string; platform?: string | null;
  script: string | null;           // null = pure native -> shared polyfill
  updatedAt: string; tools: ToolEntry[];
}
interface WebMcpIndex { version: 1; updatedAt: string; domains: Record<string, DomainEntry>; }
```

BM25 (MiniSearch, zero native deps — not yet in package.json) indexes one
document per tool: `id: "<domain>/<tool>"`, fields
domain/toolName/description/platform/paramNames. Starting boosts
3.0/2.5/1.5/1.2/1.0, fuzzy 0.2 + prefix, k=1.2 b=0.75 — all unvalidated
starting values, tuned in Phase 2 against the seed corpus, not gospel.

## 4. Polyfill (init.js — built, verified)

Single IIFE. Shim where absent; lenient wrap where native. **[LIVE]** Chrome
157 contract (verified in-page, one tool, example.com): async
`registerTool`, promise `getTools` returning handles with readable
name/description/origin, `executeTool(handle, input)` with string output
parsed back. Wrap caches name→handle by re-listing and parses string
outputs. Accepts object + string inputs everywhere (#121 shape).

`window.webmcp = { list, call, define }` + `<toolName>` shorthands.

Proven only: one-tool define/list/call round trip on one native page, both
input encodings, plus node unit coverage (shim registry, mock-native
handle resolution). NOT yet proven live: `getTools` override under load,
`toolchange` delivery, AbortSignal paths. Annotations are readable on
native handles but surfaced nowhere — "passthrough" is a Phase 1 job, not
a current property.

Phase-1 additions: `<form toolname>` hydrator (per @mcp-b/webmcp-polyfill
contract: schemas from named controls, `toolautosubmit`, `agentInvoked`/
`respondWith`), `window.webmcp._helpers` (`setInputValue` via prototype
setters, `waitFor`, `waitForStreamSettle`). Port, don't invent.

## 5. CLI

- `search <q> [--limit=10] [--domain] [--source] [--json]` — BM25 over
  merged index. YAML default, JSON on flag.
- `get <domain|url|domain/tool>` — normalize → domain lookup (parent-domain
  fallback) → unified native+custom toolset + entry URL + single `.init.js`
  path + static driver snippet. Pure-native → shared polyfill path. Hybrid/
  custom → compiled `sites/<domain>.init.js`. Unindexed domain still
  succeeds: polyfill path + `save` hint (`status: unindexed_domain`).
- `save <domain> <file.js> [--entry-url]` — vm-extract schemas (never run
  `execute()`), validate ≥1 tool, compile (header + body), merge as
  `source: custom` preserving native entries (custom wins name collisions).
- `sync` — pull `registry/index.json` + `sites/*.js`, recompile, re-merge
  local on top. Only network verb. Local never uploaded.
- `init [--stdout]` — installed path / bytes. Used by `get` internally.
- `mcp` — stdio server: `skill/search/get/save/init`.

## 5.5 Merge, bundles, ingestion (binding rules)

- Precedence is tool-level, not domain-level: managed native < managed
  custom < local custom. A local custom tool wins a name collision; a
  `sync` never deletes or overwrites a local entry, it only adds managed
  entries and updates managed ones the user hasn't overridden.
- `index.json` carries no remote `$schema`: schema ref is the repo-relative
  `schemas/v1/index.json`. No domain claims until the domain exists.
- Targeted bundles are build artifacts, never source: `get` (re)compiles
  `cache/<domain>.init.js` from header + current index state on every call
  where the domain is indexed, so a bundle can never serve a tool the index
  no longer lists. `save`/`sync` invalidate the affected bundles; there is
  no persistent bundle cache to go stale.
- One ingestion pipeline: MCP `save` takes `{ domain, entryUrl?, content }`
  with a 64KB cap and runs the exact same extract→validate→compile→merge
  as CLI `save <domain> <file>`. No second validation surface.
- vm-extract runs file top-level code in a sandbox with a stub
  `document.modelContext` collector: `execute()` bodies are captured as
  source, never invoked. Sandbox escape = treat as arbitrary-code risk, not
  as data parsing (see security todo).

**[LIVE] driver snippet rules (proven, non-negotiable):** OpenCode Browse
mount is evaluate-inline ONLY — `addInitScript`/`addScriptTag` are neutered
in the execute realm (verified: reads succeed, nothing runs, zero page
errors). agent-browser mount is `--init-script` (unverified live — prove in
Phase 4). No per-driver rendering; static skill blocks.

## 6. Skill (one file)

`search → get → driver executes`, plus `save` when raw DOM work was needed.
Static mount blocks per MCP (Browse evaluate-inline, agent-browser
`--init-script` + native invoke). Test pins driver names only, never bytes.

## 7. Seed (Phase 2)

Native platform entries from scan snapshots (Shopify 12, Mintlify 5,
GitBook, ReadMe, Cloudflare, Wix, …) as data with entry URLs. Flagship
custom/hybrid scripts last (Phase 3: ask_ai pattern + `NEEDS_DRIVER_HANDOFF`
for logged-out writes).

## 8. Non-goals

Globals, providers, install/publish registry, operated crawler (seeds are
checked-in snapshots), trust attestation beyond hint passthrough.

## 9. Phase gate

Phase 0 (done, uncommitted): polyfill + CLI skeleton + gate green + live
native-path proof + Browse evaluate-inline proof.
Phase 1: index model + sync/search/get/save + targeted bundles + renames.
Phase 2: seed data. Phase 3: custom scripts. Phase 4: live driver proofs +
skill + MCP + docs + launch. No phase starts with the previous gate red.
