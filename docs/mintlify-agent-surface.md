# Mintlify platform agent-to-agent surface (primary sources only)

Scope: official Mintlify docs pages, `https://raw.githubusercontent.com/mintlify/docs/main/discovery-openapi.json`, and live endpoints probed 2026-11-01 (`https://www.mintlify.com/docs/*`, `https://mintlify-docs.mintlify.app/*`). No secondary write-ups used. Facts only; dynamic widget end-states described only where statically observed or explicitly documented.

## 1. Native keyed paths (Discovery Assistant API v1/v2, search, page)

Base server: `https://api.mintlify.com/discovery` (discovery-openapi.json `servers`).

| Endpoint | Method + path | Auth | AI SDK compat | Credits | Thread multi-turn |
|---|---|---|---|---|---|
| Assistant message v1 | `POST /v1/assistant/{domain}/message` | Assistant key (`mint_dsc_`), `Authorization: Bearer` | AI SDK v4 (`useChat` from `ai/react`, `streamProtocol: 'data'`, `sendExtraMessageFields: true` required) | Consumes credits (message endpoint) | Optional `threadId` request field; returned as `event.threadId` when `event.type === 'finish'` (v1 schema) |
| Assistant message v2 | `POST /v2/assistant/{domain}/message` | Assistant key (`mint_dsc_`), `Authorization: Bearer` | AI SDK v5+ (`DefaultChatTransport` from `ai`, `@ai-sdk/react` `useChat` + `sendMessage`) | Consumes credits; `402` = credit limit reached | Optional `threadId`; returned as `event.threadId` when `event.type === 'finish'` (v2 schema) |
| Search documentation | `POST /v1/search/{domain}` | Assistant key (`mint_dsc_`); `401` = missing/invalid | N/A (JSON array response) | Does NOT consume credits | N/A |
| Get page content | `POST /v1/page/{domain}` | Assistant key (`mint_dsc_`); `401` = missing/invalid | N/A (JSON `{path, content}`) | Does NOT consume credits | N/A |

Details observed in primary sources:

- `domain` path param: the domain identifier from the `domain.mintlify.site` URL, found at the end of the dashboard URL (e.g. `app.mintlify.com/organization/domain` → `domain`).
- Message body required fields: `fp` (fingerprint; `'anonymous'` or a user id) + `messages`. Optional: `threadId`, `retrievalPageSize` (default 5, recommended 5), `filter` (`version`, `language`; v2 adds `groups`), `context` (`type: code|textSelection`, `value`, optional `path`/`elementId`), `currentPath` (max 200 chars).
- v1 `messages[]` shape: `{id, role: system|assistant|data|user, content: string, parts[], experimental_attachments?}` with `content` + `parts` both required. v2 `messages[]` shape: `{id, role: system|assistant|user, parts[], metadata?}` — `content` removed, `data` role removed, attachments become `parts[]` entries `{type: file, mediaType, url, filename}`.
- v1 → v2 migration status: the v2 docs page states "The v1 endpoint is discontinued and returns `410 Gone`"; the v1 docs page itself is headed "Deprecated" and points v4 users to v1 / v5+ users to v2. `threadId`, `threadKey`, `regenerate`, `retrievalPageSize`, `filter`, `context`, `currentPath` are unchanged across the migration; `X-Thread-Id`, `X-Thread-Key`, `X-Message-Id` response headers are unchanged. v1 streams the AI SDK v4 data stream (`0:"..."` lines); v2 streams server-sent events (`data: {...}` JSON, text in `text-delta` events, ends `data: [DONE]`).
- Embed-example guide (v1-era code) documents the `threadId`/`threadKey` pair: first response returns `X-Thread-Id` + `X-Thread-Key` (key returned only once, on thread creation); every follow-up must send both `threadId` and `threadKey` in the body; sending `threadId` without `threadKey` returns `404`. Persist both (example uses `localStorage` keys `assistant-thread-id` / `assistant-thread-key`) and forward them through any backend proxy unchanged, including streaming headers.
- Error semantics shared across message endpoints: `400` missing `fp`/`messages`; `401` key missing/invalid or assistant not enabled; `402` credit limit reached; `403` region / key-domain mismatch / plan lacks assistant access / IP-allowlist mismatch; `404` no site for domain or invalid `threadId`/`threadKey`; `413` max messages or input too long; `429` over 10,000 requests/hour/org; `500` retry, then contact support. Search/page share `401/403/404/429/500` with the same meanings (search `404` also = zero results; page `404` also = no search index or no page at path).
- Rate limit: 10,000 requests per Mintlify organization per hour on all four endpoints.
- Credit price: 25 credits per answered assistant question (same whether from docs site, widget, or assistant API); 0 credits when the assistant cannot answer; search and page-content cost 0. Organization shared monthly balance; per-project overage toggles; Pro contributes 10,000 credits/month.

Key types and dashboard mint location:

- Three key types exist: Admin (`mint_`, updates/agent jobs/analytics, server-side only, org-scoped, optional `read`/`write` scopes derived from HTTP method); Assistant (`mint_dsc_`, assistant/search/page only, project-scoped, proxy in production); Index (`mint_us_`, Index REST API, server-side only).
- Both Admin and Assistant keys are created on the API keys page (`https://app.mintlify.com/settings/organization/api-keys`); up to 10 API keys/hour/org; optional 7/30/60/90-day or no-expiry (`Expired` keys return `401`); optional IP/CIDR allowlist set once at creation (non-matching IP → `403`; `0.0.0.0/0` and `::/0` rejected).
- Authenticated-endpoint content rule: the assistant key can read all content including protected pages; if `groups` is omitted/empty the response includes protected pages. Mintlify does not verify group membership — the caller's backend must choose `groups` per user. On password-protected deployments `groups` restricts nothing.
- MCP client credentials are NOT API keys: create in project settings (`https://app.mintlify.com/settings/project/site`) under the Docs MCP section (section appears only when site authentication is enabled) via Generate with label + optional `groups`; copy `client_id` + `client_secret` once (secret never shown again). Exchange via `POST {site}/authed/mcp/oauth/token` (`grant_type=client_credentials`, form-encoded, `client_id`+`client_secret` in body or Basic). Response: `access_token`, `token_type: Bearer`, `expires_in: 1209600`, `refresh_token`, `scope: mcp:search`. Call `/authed/mcp` with `Authorization: Bearer ACCESS_TOKEN`. Manage in the same Docs MCP section (view groups, delete to revoke, rotate by create-then-delete; secrets stored as env vars, never committed or client-exposed).
- Admin MCP credentials are separate again: dashboard sidebar MCP → Credentials → Create credential (secret shown once, read-only tools only; edit/branch/publish/discard/comment and `read_inbox` require interactive OAuth login and return `user_principal_required`). Admin MCP itself is `https://mcp.mintlify.com`, one endpoint for all clients, OAuth login inheriting dashboard permissions; knowledge-only mode via `x-mintlify-toolset: knowledge` header narrows to `search, read, read_comments, read_page_history, list_nodes, list_branches, list_deployments`.

## 2. Public anonymous paths

### 2a. Per-site search MCP (`<docs>/mcp`, anonymous)

- URL pattern: `{site}/mcp` (e.g. `https://mintlify.com/docs/mcp`, `https://www.mintlify.com/docs/mcp`, `https://mintlify-docs.mintlify.app/mcp`). Reserved paths `/mcp` and `/authed/mcp`. Authenticated variant `{site}/authed/mcp` + OAuth flow at `{site}/authed/mcp/oauth/*`; redirect domains for both managed in dashboard; Claude/ChatGPT/Cursor/Devin always allowed, others need their redirect domain allowlisted; loopback always trusted.
- Discovery (no config, served automatically): `GET {site}/.well-known/mcp` ≡ `GET {site}/.well-known/mcp.json` → `{version, transport: http, url, servers: [{name: public, url, transport: http, authentication: none}, {name: authenticated, ... oauth2} (only when site uses auth)]}`. Server cards: `GET {site}/.well-known/mcp/server-card.json` (single) and `server-cards.json` (`servers[]`, always ≥ public card). Live probe `https://www.mintlify.com/docs/.well-known/mcp.json` returned the public-only variant; `https://mintlify-docs.mintlify.app/.well-known/mcp.json` likewise; `https://cline.mintlify.app/.well-known/mcp.json` advertises canonical `https://docs.cline.ai/mcp`.
- Exact live tools on `https://www.mintlify.com/docs/mcp` (`tools/list`, Streamable HTTP, one JSON-RPC per POST): `search_mintlify`, `query_docs_filesystem_mintlify`, `submit_feedback` (3 tools). Docs prose describes the same three as Search / Query docs filesystem / Submit feedback.
  - `search_mintlify` input schema (live): `{query: string (required), language?: string (default en)}`, `additionalProperties: false`. Docs prose adds optional `version` and `language` search params. Returns snippets with titles + links.
  - `query_docs_filesystem_mintlify` input schema (live): `{command: string (required)}` — read-only shell against a virtualized in-memory filesystem rooted at `/` containing only that site's doc pages + OpenAPI specs. Supported: `rg, grep, find, tree, ls, cat, head, tail, stat, wc, sort, uniq, cut, sed, awk, jq`; stateless per call (cwd resets to `/`); 30 KB output cap per call. Page at URL `/some/page` is read as `/some/page.mdx`; OpenAPI mounted under `/openapi/*.json`. Workflow per description: search tool first for broad queries, filesystem tool for exact regex/structural reads and multi-file `head`.
  - `submit_feedback` input schema (live): `{path: string minLength 1 (URL path without `.mdx`), feedback: string minLength 1}`, both required. Records unhelpful feedback in analytics. Read-only otherwise; server is read-only and scoped to that site's public content + skill resources. Live `initialize` instructions repeat: prefer server over prior knowledge, cite site results, do not claim private access unless the session is authenticated.
  - Note: the static `server-card.json` for the same site advertised only the first two tools (no `submit_feedback` entry) while live `tools/list` returns all three — clients must call `tools/list`, not trust the card's `tools[]` (tool names are site-specific per docs: `search_<site>`, `query_docs_filesystem_<site>`).
- MCP rate limits: 5,000/hour per user (IP) on server config; 10,000/hour per site on search; 10,000/hour per site on query-docs-filesystem; 5,000/hour per site on authenticated search; 5,000/hour per site on authenticated query-docs-filesystem. Over-limit → HTTP `429`, retry after rolling-hour window.
- Indexing scope: only `docs.json` navigation pages are indexed unless `seo.indexing: "all"`; hidden pages excluded unless that flag; `noindex: true` frontmatter excludes a page; `.mintignore` matches are never processed/indexed. Authenticated sites: index = public pages + pages the user may access by `user groups`.
- WebMCP (Pro/Enterprise, automatic, no setup): registers 5 tools on-page via `navigator.modelContext` — `search_docs`, `read_page`, `get_site_overview` (returns `llms.txt`), `read_skill` (`skill.md`), `navigate_page`. Docs prose also notes Pro/Enterprise sites register these in WebMCP-capable browsers so agents can search/read without a separate connection.
- Skill resources: the search MCP also exposes `skill.md` files as MCP resources; group-gated skills only for matching authenticated users; unauthenticated users of public `/mcp` see only `public: true` skills.

### 2b. `llms.txt` / `llms-full.txt` (+ splits, headers)

- URLs: `{site}/llms.txt` ≡ `{site}/.well-known/llms.txt`; `{site}/llms-full.txt` ≡ `{site}/.well-known/llms-full.txt`; page links use `.md` suffix so agents fetch Markdown directly. Fully authenticated sites: both files require auth; partially authenticated: both public but list only public pages.
- `llms.txt` structure: H1 site title; blockquote `docs.json` description; `Agent Instructions` block (from `markdown.instructions`); grouped page links in `docs.json` nav order with frontmatter-description text (first paragraph, ≤300 chars); `OpenAPI Specs` / `AsyncAPI Specs` link sections; `Optional` external-link section; Mintlify attribution line (omitted when branding removed). Non-nav pages with `seo.indexing: "all"` append alphabetically. Default language + default version only.
- 100,000-character cap: oversized `llms.txt` keeps a directory-style main file with an `Indexes` section of `/_llms/*.txt` links (breadcrumb + page count + description), recursive; each index served as `text/plain` at `.txt` and `text/markdown` at `.md`; base-path sites prefix both (`{base}/_llms/*` must be forwarded through reverse proxies). `llms-full.txt` has no such cap: single file of every page's title + URL + description + full Markdown (visibility rules: `for="agents"` included, `for="humans"` excluded).
- Custom files: repo-root `llms.txt` / `llms-full.txt` (must keep H1 title) override the generated same-name file; deleting restores generation. On authenticated sites a custom file linking any non-public page becomes auth-only; anonymous visitors fall back to the generated public-only file.
- Discovery headers (live-verified on `https://www.mintlify.com/docs`): `Link: </docs/llms.txt>; rel="llms-txt", </docs/llms-full.txt>; rel="llms-full-txt", </docs/.well-known/api-catalog>; rel="api-catalog", </docs/.well-known/mcp/server-card.json>; rel="mcp-server-card", </docs/.well-known/agent-card.json>; rel="agent-card", </docs/.well-known/agent-skills/index.json>; rel="agent-skills"` plus `X-Llms-Txt: /docs/llms.txt`. Sent on every response including Markdown and 404s; base-path-prefixed when applicable; authenticated sites add `rel="oauth-protected-resource"`. Live `https://mintlify-docs.mintlify.app/` returns the non-prefixed variant.
- Adjacent discovery (same family, observed live): `GET {site}/.well-known/agent-card.json` (A2A 0.3 card: `protocolVersion 0.3`, `preferredTransport HTTP+JSON`, `capabilities {streaming:false, pushNotifications:false}`, `skills[]` → `/.well-known/agent-skills/{slug}/skill.md`); `GET {site}/.well-known/agent-skills/index.json` (agent-skills 0.2.0 manifest with `sha256` digests); legacy `/.well-known/skills/index.json`; `{site}/skill.md` (auto-generated, ≤24 h refresh, public sites only); `GET {site}/.well-known/api-catalog` (live `200`, `application/linkset+json`, only when spec download enabled).

### 2c. Chat widget / on-site assistant panel

- Deep-link (documented): append `?assistant` to any docs page to open the chat panel with no message; `?assistant=<message>` (URL-encoded) to open AND auto-submit `<message>` as the first message (e.g. `https://yourdocs.mintlify.site/quickstart?assistant=How%20do%20I%20get%20started%3F`). Use for email/support/in-app/banner/onboarding links. Keyboard: `Cmd+I` / `Ctrl+I`. UI placement: button next to search bar + bar at bottom of page; panel opens on the right side of docs. Highlighted text → `Add to assistant` context button; code blocks → `Ask Assistant` context button; file attachments up to 5 MB each, ≤10 per message (images JPEG/PNG/GIF/WebP/SVG; PDF; code/text extensions enumerated in docs).
- Embed widget (off-site): hosted script `https://widget.mintlify.com/v1/embed.js`; `window.MintlifyAssistant.init({id: YOUR_WIDGET_ID, ...})` (only required option is the public widget ID; dashboard Widget page manages enabled state, allowed origins, attachments, bot protection, deflection contact form). Presentation `variant: widget|modal|panel`, closed Shadow DOM (blocks cross-site style regressions; no arbitrary CSS). Browser API: `init/open/close/ask(question, {source, open:true, focus:true})/update/reset/destroy`; `ask()` opens then sends; `update()` deep-patches without clearing the conversation; `identity` change starts a new conversation. CSP must allow `script-src https://widget.mintlify.com`, `connect-src https://widget.mintlify.com + https://api.mintlify.com + https://ph.mintlify.com (+ https://*.hcaptcha.com / https://js.hcaptcha.com` when captcha on), `font-src https://widget.mintlify.com`, optional `nonce` propagation.
- `siteconfig` (live-verified): client fetches `{BASE_PATH}/_mintlify/assistant/siteconfig` (JS: `` fetch(`${R.BASE_PATH}/_mintlify/assistant/siteconfig`) ``). Live `GET https://www.mintlify.com/docs/_mintlify/assistant/siteconfig` → `200 text/plain`, 234-byte EdDSA JWT (`alg EdDSA`); decoded payload observed: `{"p":"hcaptcha","sk":"c696923c-678e-41ee-94c4-0cdec7d453d4","sub":"mintlify","exp":1793558024}`. Client schema validates `p ∈ {turnstile, hcaptcha}`, `sk` = site key, `exp` = expiry. Loader covers both providers (`turnstile`+`hcaptcha` script URLs, timeouts, `__hcaptchaOnLoad`).
- Captcha gating: dashboard Assistant settings → Bot Protection → Invisible Captcha toggle (≤10 min to propagate; privacy-friendly, invisible to nearly all visitors). Live JS bundles both `assistant-captcha-server` and `assistant-captcha-client` experiment flags and per-request trust-token plumbing. Corporate-network troubleshooting lists `leaves.mintlify.com` (assistant API), `*.mintlify.dev` (streaming/supporting), `*.mintlify.com` (dashboard/API/analytics), `hcaptcha.com` + `*.hcaptcha.com` (CAPTCHA). CSP pages repeat `hcaptcha.com` + `*.hcaptcha.com` allowlist requirement; widget CSP adds `https://js.hcaptcha.com` (`script-src`) and `https://*.hcaptcha.com` (`connect-src` + `frame-src`).
- Panel selectors (live static HTML, `https://www.mintlify.com/docs`): `#assistant-entry` + `#assistant-entry-mobile` (`aria-label "Toggle assistant panel"`), `#chat-assistant-sheet` (`.chat-assistant-sheet`, `aria-hidden`), `#chat-assistant-textarea` + `.chat-assistant-input` (`aria-label "Ask a question..."`, `autocomplete off`, `rows 2`), `.chat-assistant-send-button` (`aria-label "Send message"`), `#chat-assistant-sheet-container`, `[data-assistant-state]` (`open|closed` observed as `closed`), `[data-assistant-layout="legacy"]`, `[data-assistant-bar]`. No `role="dialog"` present in the static snapshot. File input `accept` list observed inline matches the documented attachment types.
- Headless vs headed: primary docs state only that bot protection is "invisible to nearly all visitors" with an Invisible Captcha toggle; no primary doc describes headless-detection differences, auto-submit-vs-toggle timing, or end-state enablement — those are runtime behaviors and must be probed live per site (see §3 for the static enabled-vs-disabled signal that is observable without interaction).

## 4. What `get_agent` must carry (factual inventory for zero-fumbling runs)

Derived strictly from §§1–3 — each item names the exact value to capture per target host before driving it:

1. Deep-link template: `{pageUrl}?assistant={urlencoded-first-message}` for auto-submit, `{pageUrl}?assistant` for open-only. Both forms are documented; the task's "auto-submit vs toggle" is exactly this parameter difference.
2. Panel selectors (capture per host, do not hardcode): entry trigger `#assistant-entry` (+ `#assistant-entry-mobile`), panel `#chat-assistant-sheet` / `[data-assistant-state]` (poll `open|closed`), composer `#chat-assistant-textarea` (`.chat-assistant-input`), submit `.chat-assistant-send-button` (`aria-label "Send message"` at rest), header `.chat-assistant-sheet-header`. Live `www.mintlify.com/docs` evidence above; re-scrape per host because disabled hosts expose only `[data-assistant-state]`.
3. Three-state send machine (runtime-read, not documented): rest (`Send message`) → in-flight (`STOP`, aborts stream) → rest. The task's "two-phase STOP→arrow→STOP→arrow" refinement is not in primary sources — treat the button's accessible label + enabled/disabled + visible glyph as the ground truth each poll and never assume a fixed phase count.
4. Completion criterion + timing: no documented "done" event exists for the panel; the keyed API's stream terminators are `data: [DONE]` (v2) / v4 data-stream end (v1), while the panel requires DOM polling (network idle on `leaves.mintlify.com` + `*.mintlify.dev` AND a full poll interval with zero text delta AND the send control back at rest). Quote the criterion per run; do not fix a sleep duration.
5. Multi-turn rule: capture `X-Thread-Id` AND `X-Thread-Key` from the first response (key issued once) and resend both on every follow-up; `threadId`-without-`threadKey` → `404`. Applies to keyed API and backend-proxied widget flows.
6. Limits to enforce per call: message `currentPath` ≤ 200 chars; attachments ≤ 5 MB each, ≤ 10 per message; search `pageSize` 1–50 (default 10), `scoreThreshold` 0–1; org rate cap 10,000/hour (assistant/search/page) + MCP caps (5,000/hour-IP config; 10,000/hour-per-site search and filesystem; 5,000/hour-per-site authenticated variants; `429` = back off, rolling-hour window); credit cost 25/answer, 0 for no-answer/search/page; secret-redaction (`[REDACTED_SECRET]`) means never paste real credentials into the panel.
7. Auth routing per host: anonymous → `{site}/mcp` + `llms.txt`/`skill.md`/agent-card discovery; site-auth → `{site}/authed/mcp` with client-credentials token flow (`/authed/mcp/oauth/token`, `expires_in: 1209600`); dashboard/team writes → `https://mcp.mintlify.com` OAuth only (credentials are read-only); keyed retrieval → assistant `mint_dsc_` key from the API-keys dashboard page, never embedded client-side in production.
